How the density estimate is used

For a featured size: minimum food count = ceil(points to next size / item reward). Author ceil(1.5 × points to next size / reward) items at generation. A first estimate of reachable area in six seconds is 2 × hole radius × movement speed × 6; dividing the minimum count by this area estimates useful local density. Collisions, falling and route choice reduce actual collection, so the fixed layout is then measured in full trials.

Microbial density belongs in a small patch inside a block, not uniformly across a 20×20 city block. The table gives the count for each authored size band. Density.csv includes both the estimated sweep density and the actual density within its placement band. Animal/person growth tiers use stationary alternatives so fleeing actors cannot starve progression. Interaction and performance behavior

  • Oversized nearby props wobble in place; collision footprints stay anchored. Permanent barriers never become food.
  • Tables and containers spill existing contents. Contents retain their IDs and score separately when swallowed.
  • People and animals visibly react and flee away at double speed. Existing crosswalk and crowd budgets remain.
  • Grouped points, optional sound, rim feedback and patch/block completion notices acknowledge actions without bonus multipliers.
  • Small items normally drop in place; large objects tip and travel toward the hole center. During sustained slow frames, items no larger than 22% of hole radius disappear at first rim contact, retaining exact-once scoring. Normal presentation returns after recovery.
  • Modern WebGL sedan/apartment variants use the approved polished models. Shared masonry textures improve other building walls. Software gameplay retains simpler models.
